日期：2026-10-18（Asia/Shanghai）

用户要求先查看第 2、5、7、8 节的 UI，已制作 [可点击前端评审原型](D:/llm/agent/ai-workbench/prototypes/workbench-ui/index.html)及[体验说明](D:/llm/agent/ai-workbench/prototypes/workbench-ui/README.md)。该原型使用演示数据、模拟生成与语音流程，未接入真实服务；不等于正式产品实现或整稿审批。

## 1. 产品目标与用户

构建个人使用的 Windows AI 工作台，参考 WorkBuddy 的工作区、任务会话、Agent、工具与成果组织方式，自行实现统一底座。首批交付面试题整理 Agent 与 AI 面试官 Agent，随后完善课程学习复盘。

用户有 5 年 Java 开发经验，正在学习 Python、RAG 和 Agent 开发，使用 PyCharm 和语雀；求职方向包括 Java、Python 后端兼 AI、Agent 应用开发。当前没有面试题库，需要从零建立。已有 Java 经验不等于同等 AI 经验，系统按方向分别记录训练情况。

首版成功结果：用户能关联一个项目、配置模型、建立一批有来源标记的训练题，完成一次有追问的文字或语音面试，查看逐题反馈，退出重开后继续训练。所有这些操作在同一工作台中完成，题库和报告可独立查询、编辑及导出。

## 2. 已确认范围与本轮设计默认

### 用户已确认

1. 工作区与资料关联。
2. 会话与任务管理：历史、取消、保存进度后恢复。
3. Agent 配置与切换。
4. 可见的执行步骤、工具结果和错误。
5. 模型与工具管理：DeepSeek、语音服务、统一工具入口与最小 MCP 接入。
6. 成果预览与本地保存。

其他已确认条件：允许云端处理，面试支持文字和语音，先交付题库与面试官，再完善课程复盘。

### 为形成可评审流程而提出的默认设计

- 个人单用户、多工作区，不增加登录、团队协作和付费系统。
- 首版两个可用内置 Agent。自定义 Agent 从任务模板创建，配置提示词、模型和允许的工具；内置面试流程的状态规则不靠提示词任意改写。
- 一批候选题默认生成 10 道，用户可调整；批量建库与真实面试分别使用任务类型，不混为同一长对话。
- 面试默认 20 分钟、5 道主问题，每题最多 2 次追问；时间和题目数均为软目标，可提前结束、跳题或继续。达到默认值后不强行截断正在提交的回答。
- 同时提供训练模式与模拟模式：训练模式每题追问结束后反馈；模拟模式结束后统一反馈。
- 语音先做逐轮回答：点击录音、停止、转写、核对、提交。题目始终显示文字，首版不以持续监听或实时双向语音通话为前提；语音播报留给后续迭代。
- MCP 首版只接入用户主动配置的本地 stdio 服务，提供连接状态、工具列举、选择与调用；远程 OAuth、多服务市场不是首版验收前提。

这些默认可在本轮书面评审中修改；没有把尚未决定的体验伪装成用户已经选择。

## 3. 方案取舍与推荐

| 组织方式 | 优点 | 取舍 |
| --- | --- | --- |
| **统一工作台 + 明确的 Agent 任务流程（推荐）** | 资料、题库、会话共用，职责清楚，任务过程可恢复，能继续增加 Agent | 需要先实现最小共享任务与数据层 |
| 一个通用助手自动分派所有任务 | 自然语言入口统一 | 首版任务边界和面试阶段更难控制，容易把结构化成果留在聊天里 |
| 分开建设题库工具、面试工具和学习工具 | 单个页面容易起步 | 后续重复维护模型、历史、文件和来源，用户需要来回搬运内容 |

推荐方案符合已确认的 WorkBuddy 式平台方向。第一版采用明确入口及显式交接，不增加一个尚无必要的自主多 Agent 调度系统。

参考的是本地 WorkBuddy 5.8.3 发布包中已有静态证据支持的功能，完整出处见[功能映射](D:/llm/agent/ai-workbench/docs/product/2026-10-18-workbuddy-feature-adaptation.md)。

| 借鉴点 | 本产品落地 |
| --- | --- |
| 工作区、会话、历史与恢复 | 项目和资料绑定工作区，建题任务与面试任务各有记录与进度 |
| 任务执行、事件回传与工具调用 | 任务面板展示正在进行的步骤、工具及结果，允许取消和从已确认步骤继续 |
| 模型设置、工具及 MCP | 统一模型、语音服务与工具设置，不要求每个 Agent 单独重复配置 |

现有逆向没有完整恢复 WorkBuddy 内部 CLI 的 Agent 循环。该产品设计是依据功能和模块职责独立构建，不依赖其运行中的账号、私有服务或其 CLI。不会按现有逆向中未覆盖的部分承诺行为相同。

## 5. 页面与交互结构

用户在首轮原型评审中明确要求参考 WorkBuddy 截图调整布局：左侧导航全局共用，中央首页划分“办公 / 开发 / 设计”三个模块，“个人成长工作区”不再作为顶部固定入口。第二轮可点击原型已按此方向更新，用户于 2026-10-18 回复“可以”，确认采用本版布局作为后续产品界面的基线。

左侧共用导航为新建任务、助理、专家·技能·连接器、定时任务、资料库和更多，下方保留任务历史与空间列表。中央三个模块改变任务快捷入口和建议内容，不替换全局导航。工作空间作为当前任务上下文放到输入框下方，与访问方式、资料和模型配置放在任务附近。

办公首批承载面试题整理和面试官；开发、设计首页本轮作为可点击布局与任务草稿展示，不表示用户已批准新增完整开发执行、设计生成或后台调度能力。任务内继续组合对话、步骤和成果，不为每个 Agent 建一套互不相通的聊天系统。

| 页面或区域 | 首版内容 |
| --- | --- |
| 工作台首页 | 中央办公/开发/设计切换、任务输入、快捷入口与建议任务；任务附近选择空间，全局侧栏查看历史和空间 |
| 工作区 | 名称、岗位方向、关联项目目录、选中的材料及来源状态；移除关联不删除原项目 |
| Agent 中心 | 两个内置 Agent，自定义配置，选择模型及工具；新增配置后可创建普通任务 |
| 任务详情 | 任务目标、对话或答题区、执行步骤、错误与取消操作、相关资料和成果页签 |
| 题库 | 从办公或更多应用进入，支持主题、岗位、难度、来源、状态筛选；题目详情、回答要点、追问、修订与选择面试 |
| 面试记录 | 逐轮问题与回答、已用提示、训练反馈或最终报告、继续或重新练习 |
| 复习清单 | 面试发现的知识缺口、关联原题和解释，手动开始补练；首版不自动定时运行 |
| 设置 | DeepSeek 连接、语音服务、密钥状态、MCP 服务及工具范围、本地数据位置 |

宽窗口下，左侧为全局导航，中间为当前任务，右侧为可收起的资料和成果检查区。检查区共用“执行步骤 / 参考资料 / 成果”页签；本轮原型在宽度不超过 1020px 时改为上下排列，点击成果卡片会定位到检查区。所有录音和执行状态用文字及图标共同表示，按钮支持键盘操作。

### 本轮继续设计：任务内页交互

用户在首页布局确认后要求“继续设计”。以下交互已进入可点击评审原型，属于本轮设计细化；正式产品能力仍按本文验收，不以演示状态替代真实集成。

1. **统一任务工作台**：任务头部显示目标、状态、模型和所选空间；中间显示用户目标、助手回复、简明处理计划和成果卡片，下方继续补充要求。侧栏与首页共用。
2. **执行步骤**：可展开每步查看输入范围、处理摘要和结果状态；运行中可取消，失败后保留目标与资料范围，从失败处重试。恢复不自动重复请求。
3. **参考资料**：展示任务提交时的空间、访问方式和所选材料快照，支持内容预览；切换首页空间不改变旧任务范围。原型预览为固定示例，不来自项目真实文件。
4. **成果检查**：预览或编辑 Markdown，切换页签保留编辑内容；保存是明确动作。继续对话不直接覆盖已经编辑的成果。进入题库整理会复制当前成果到新任务的输入快照；候选题仍为示例，没有把 Markdown 自动解析成真实结构化题库，也不改原成果。
5. **面试页**：问题与回答区优先，旁边保留本轮进度、已提交回答和来源；追问时可以对照自己的原话。提示与输入方式留在回答记录中。
6. **模型设置**：分开呈现文本模型、语音服务与工具连接；连接成功和失败各有可读状态，失败不清空任务。原型密钥输入禁用、连接状态均为演示。
7. **任务记录**：提供全部、待处理、已保存成果和草稿入口，重开任务查看原目标、状态、对话与成果；中断任务由用户选择继续。

本轮原型使用确定性演示步骤，通用任务和成果保存在浏览器 localStorage；没有读取真实项目、发起模型或语音请求、启动 MCP 进程。正式产品仍需实现状态服务、本地数据库和真实适配器。

## 6. 工作区与资料

- 可建立 Java 面试、Python/AI 面试等工作区；岗位只是标签，不复制一套题库数据。
- 关联学习项目采用用户选定目录，首版只读。选择文件或变更后展示实际上下文范围，不自动将全项目发给模型。
- 第一版重点支持粘贴文本、Markdown、TXT、JSON 及 Java/Python 等源码文本。PDF、PPT、课程音视频保留为后续学习模块的输入；不将首版关联文件等同于已支持所有格式解析。
- 默认排除密钥配置、凭据文件、二进制、依赖与缓存目录；超大文件提示缩小范围。特殊文件由用户明确选择后才进入读取流程。
- 每份来源保存名称、路径或 URL、内容摘要/哈希、读取时间与引用位置。项目变更后，将旧引用标为可能过期，不无声替换历史面试依据。
- 题目中的本地代码位置必须确有读取依据。材料没有明确说明时，模型建议标为推测或待核对，不能编造代码行号、课程时间点及工作经历。

## 7. 面试题整理 Agent

### 完整流程

1. 用户选择工作区、岗位、主题、数量，可选相关项目代码和材料。没有任何材料也可根据所选主题生成候选训练题。
2. 显示本次处理范围、选定模型和来源类型，开始任务。
3. 执行步骤分别为读取材料、归纳主题、生成候选题、字段校验及重复检查。每一步有状态和错误信息。
4. 模型输出经过结构校验后作为草稿呈现，用户可编辑、移除或接受部分题目。
5. 点击保存后写入题库，显示新增、更新和未保存项；同一次保存重试不创建重复题。
6. 用户从已保存题目选择开始面试，显式交接题目版本、来源和岗位设置给面试官。

### 每题内容

保存题干、主题、岗位标签、建议难度、考察意图、回答要点、可接受的不同方案、追问方向、来源类型和引用、内容版本、用户修订。

来源分为模型生成训练题、项目代码衍生题、用户导入资料题及已核验的外部资料题。首版不默认爬取面经，也不把模型生成题标成某公司真题。参考答案允许修改；不同合理方案不能因为与参考措辞不同被判错。

重复检查先按规范化题干识别明确重复，主题近似的题目只提示用户比较与合并，不自动删除可能考察不同角度的题。

## 8. AI 面试官 Agent

### 准备与开始

用户选择一个主方向、训练或模拟模式、选题范围、文字或语音输入，以及预期时长。初始 Java 背景为 5 年，Python/Agent 深度单独设置或通过回答逐步调整。主问题使用已保存题目版本；临场追问保存为本轮生成内容。

用户没有题库时，先引导建立一小批候选题并确认，不能进入一个没有题目、不断等待的空面试。

### 回答与追问

- 每轮只展示一个问题，回答提交后再决定追问、进入下一题或结束。
- 用户可以跳过、不知道或结束；这些状态独立记录，不强迫编造回答。
- 追问应引用回答中实际提到的内容，询问原理、取舍、边界或项目验证；不声称用户没说过的话。
- 训练模式允许方向、定位、骨架、参考答案逐级提示。已看提示记录下来，之后表现不直接等同于独立作答。
- 模拟模式默认不在过程中展示参考答案，结束后统一给出反馈；用户提前结束仍可生成已完成部分的报告。
- 同一轮中可将输入改为文字，语音失败不会丢失已经提交的回答。

### 语音路径

用户点击录音后才访问麦克风，录音标识、时长、停止按钮始终可见，单次回答最长 3 分钟，达到上限自动停止但不自动提交。

停止后调用已配置的语音识别服务，将转写显示为可编辑文本；用户核对技术名词后提交。原音频属于本机可管理的会话附件，可以删除；不会因删除音频而删除已确认的文字回答。语音失败可重试或改文字，不能将识别失败直接判为知识错误。

首版问答节奏为逐轮交互，题目显示文字，不包含实时双向语音、语音打断和持续监听。麦克风面试录音与课程播放器声音采集是不同工具，不共享录制授权或启动状态。

### 反馈与报告

每题反馈包括正确点、具体遗漏或错误、依据不足的部分、改进示例与后续复习方向。训练模式逐题显示，模拟模式统一显示。

本轮收口采用有依据的文字反馈：原回答、参考方向、具体遗漏和下一步补练，不要求总分、雷达图或固定维度等级。信息不足单独标注；当前原型固定示例反馈不代表能力评价。此决定替代早期 0–3 级训练参考建议，正式规则见 PRD FR07。

根据已确认文字评价内容；没有分析音频时，不给语速、发音、停顿或情绪结论。不能根据声音或答题方式推断人格。用户可将薄弱项加入复习清单，或交给题库整理 Agent 生成待确认的补强题。

## 9. Agent、模型与工具底座

### 最小逻辑架构

```text
桌面界面
  → 本地任务与会话服务
      → 题库整理流程 / 面试状态流程 / 自定义普通 Agent 任务
      → 模型与语音服务适配
      → 资料读取、题库操作及 MCP 工具入口
      → SQLite 数据与本地附件
```

UI 负责交互，本地服务拥有任务状态与数据写入。模型返回的是文本、结构化候选内容或工具请求；程序校验参数、权限和当前阶段后再执行工具。面试“等待回答”不能由模型文本直接跳为“已提交”，保存和取消也不能只靠提示词保证。

实现时先选择一条桌面到本地服务的通信方式，不同时建设多种传输。是否使用独立后台进程以及具体桌面/Agent 框架属于后续技术方案与实施计划的决策；这里规定的是必需职责和数据契约，不照搬 WorkBuddy 的全部进程。

### 模型设置

DeepSeek 为默认文本模型，设置保存供应商、接口地址、模型标识、超时与连接状态。语音服务单独配置，不假定文本模型一定支持语音识别。密钥放入操作系统安全存储，前端只读到是否已配置，日志及报告不得输出密钥。

连接测试使用不含课程或项目资料的小请求，显示结果；测试或生成真实请求可能产生服务商费用，界面应明确调用状态。模型具体标识和当前接口能力在技术实现前核对服务商文档。

### MCP 和工具

首版提供一个本地 stdio MCP 连接器，用户主动配置程序、参数及所需环境配置。连接器只管理由本工作台启动的进程，退出时清理自己的连接，不终止无关程序。

显示可用工具及其说明，用户选择 Agent 可使用的工具。参数需按声明校验，单次调用有超时和可见状态。文件读取限制在选定范围，写文件、删除及外部发布类工具按明确授权执行，不能从工具名称推断安全等级。

工具结果是外部数据，不作为修改工作台规则或扩大权限的指令。MCP 不可用时，普通建题和文字面试仍可使用内置资料与题库工具；有依赖的任务具体说明阻塞原因。

## 10. 任务状态、取消和恢复

通用任务状态：`draft → queued → running → waiting_user → completed`，另有 `failed / cancelling / cancelled / interrupted`。每个状态转换记录事件。

建题任务的用户确认、语音转写校对和面试等待回答属于 `waiting_user`，不应显示为模型一直执行。面试另外保存当前题目、主题序号、追问次数、未提交输入和已确认回答。

取消请求传播到活跃的模型、语音和工具调用，先显示取消中，待本地停止后记录取消。远端无法中止时仍丢弃迟到结果并说明可能已经产生请求费用；迟到结果不得越过取消状态触发保存或外部写入。

应用退出或异常后，未完成活动任务标记为中断；重新打开时显示恢复入口。恢复仅基于已保存状态，不自动重复上一条模型请求、语音上传或外部副作用。用户确认从某步继续。

首版同一时刻最多执行一个主动 AI 任务，等待用户回答的任务不占执行槽；其他任务排队。先保证状态可靠，多个任务并行执行作为后续扩展。

## 11. 数据保存与来源

使用本地 SQLite 保存结构化数据，附件存为本地文件，二者通过稳定 ID 关联。逻辑实体如下：

| 实体 | 主要内容 |
| --- | --- |
| 工作区与资料来源 | 项目关联、选定材料、文件/URL引用及内容指纹 |
| Agent 配置 | 版本、任务说明、模型引用、允许工具及模板类型 |
| 任务与任务事件 | 当前状态、输入范围、执行步骤、错误和恢复点 |
| 题目与版本 | 题干、要点、追问、岗位主题、来源与修订 |
| 面试与轮次 | 模式、题目版本、问题、回答、输入方式、提示及追问 |
| 反馈、报告与复习项 | 依据回答形成的评价、生成版本、复习关联与用户处理状态 |
| 附件和服务配置 | 本机音频/导出文件位置、服务配置及密钥引用 |

题目编辑生成版本，面试引用当时的版本，不因后来编辑改变历史提问。提交回答和保存题目使用操作 ID 防止重复提交。报告重生成保存新版本，用户可比较，不覆盖已经修改的报告。

支持按题干、知识点及标签进行本地关键词查找，首版不要求另建向量数据库。导出为 Markdown 报告与结构化 JSON 题库，不导出服务密钥。

移除工作区关联只改变本机记录，不删除原项目文件。删除题目不破坏历史面试中已保存的题目快照。个人数据删除在工作台中提供清楚范围；外部服务保留行为不能通过删除本地文件保证。

## 12. 错误、可靠性与可观察性

| 情况 | 处理 |
| --- | --- |
| API 密钥缺失或失效 | 留在当前任务，说明需要更新设置，保留用户输入 |
| 限流、超时或网络错误 | 显示失败步骤及有限重试入口，不无限重试，不重复已保存内容 |
| 模型输出结构不完整 | 保留草稿原文与错误，允许重生成；没有通过字段校验的题目不自动入库 |
| 文件缺失或代码更新 | 标记来源不可用/过期，允许重新关联，不编造引用 |
| 麦克风拒绝、识别失败 | 可重试或切换文字，已提交回答保持不变 |
| 工具进程崩溃 | 记录工具错误和连接状态，不使整个界面或题库不可用 |
| 本地写入失败或空间不足 | 不提示保存成功，保留可恢复草稿并显示实际失败 |
| 程序异常退出 | 重新打开列出中断任务和最后保存位置，不自动重新执行副作用 |

执行轨迹展示步骤、工具名称、参数摘要、结果、时间与错误；不将内部思维链作为界面能力。日志保留必要技术状态并过滤密钥，不默认记录原始录音和全量源码。

## 13. 首版不包含及后续迭代

首版不包含团队协作、账号计费、自主 Agent 团队调度、远程 MCP OAuth、公开插件市场、Office 完整编辑器、通用电脑控制、自动执行用户项目代码、真实面试作弊辅助，以及自动投递或对外消息发送。

第二阶段按已确认方向补齐学习复盘、语雀保存、复习调度、Skills 管理与更多工具。课程复盘保留 10 分钟快速回顾、20～30 分钟小练习和逐级提示模式。

已知课程输入缺口：深造播放器音频可获取，窗口捕获由于 WDA_MONITOR 得到黑屏，在线与离线课程均依赖同一播放器。现有工作台设计不承诺该问题已经解决，也不依赖其解决来交付面试模块。后续验证独立课件、老师源码与转写关联时，明确区分材料关联和原视频画面恢复。

## 14. 验收与测试

以下检查必须针对真实数据流或可复现的服务替身进行，不能只凭界面出现按钮或模拟延时判为通过。使用真实云端调用验证时单独记录模型及语音服务配置，密钥不进入报告。

| 编号 | 验收场景与通过条件 |
| --- | --- |
| A01 | 从新建工作区关联一个项目并选择文件，模型请求只包含选定且可读取的内容；排除文件不会被无意发送 |
| A02 | DeepSeek 配置、非敏感连接测试、缺失/失效密钥提示均可用；密钥不在界面配置响应、日志或导出文件出现 |
| A03 | 没有已有题库时生成一批候选题，编辑和选择部分保存；保存结果字段完整、来源可区分，重复点击不重复创建 |
| A04 | 从题库开始文字面试，一次一个问题，有基于回答的追问；正确记录跳题、不知道、提前结束及生成报告 |
| A05 | 完成一次语音回答，录制状态可见，停止后可编辑转写，确认后进入同一面试流程；识别失败可改文字且不丢已提交回答 |
| A06 | 训练模式在每题结束后反馈，模拟模式在结束后反馈；看过提示有记录，不被当作独立答对 |
| A07 | 在生成或工具调用期间取消，停止后迟到事件不触发题目保存、报告覆盖或其他副作用 |
| A08 | 退出并重新打开，题库、记录和报告仍在；中断面试从已保存轮次由用户选择继续，不重复提交上一题 |
| A09 | 配置一个本地 MCP 测试服务，连接、列工具、执行允许工具及超时处理可观察；越界文件或未允许工具执行被拒绝 |
| A10 | 从模板建立一个自定义 Agent 配置并创建普通任务，可使用允许工具；不修改内置面试状态规则或获取额外权限 |
| A11 | 题目修订不改变已有面试快照，来源文件变更能提示过期；本地关键词查找和 Markdown/JSON 导出有效 |
| A12 | 一个完整切片可用：建立 10 道候选题 → 保存至少 5 道 → 完成一轮含文字及语音回答的面试 → 查看有依据的反馈 → 加入复习清单 → 重开后继续练习 |

关键状态、权限范围、取消/重试幂等和面试阶段转换做自动化检查；语音识别质量、实际延迟和生成内容质量做小样本人工核对；桌面页面做实际交互验证。测试中不会修改 `D:\python\tiangong_agent` 的代码来伪造学习结果。

## 15. 设计评审与交付顺序

用户已要求本轮持续完成设计与 PRD，现已整理页面流程、状态、范围、默认和验收，不再以逐页确认阻断本轮交付。技术方案与实施计划属于后续工程工作，需核验技术栈、依赖版本、语音供应商及验收命令。当前 PRD 为主文档，本节保留早期交付顺序参考；不把设计完成解释为真实服务已接入。

建议实现时按可运行切片交付：

1. 桌面最小底座、模型配置、工作区与本地保存，题库整理打通。
2. 文字面试、阶段状态、追问、反馈、恢复与复习清单。
3. 语音回答、MCP 最小接入、自定义 Agent 配置和完整首版验收。

课程学习模块在后续迭代补齐，不取消；不先搭一个没有可用任务的庞大空平台。当前目录包含分析产物、设计文档和可点击评审原型，尚未创建正式产品工程，也没有配置或调用用户的模型/语音 API。
