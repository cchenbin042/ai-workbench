# Txxx：任务名称

> 创建方式：复制到 `tasks/Txxx-YYYY-MM-DD-short-name.md`；替换编号、日期和标题，按新文件位置填写相对链接，再删除提示文字。
> 单次任务可跨日、可包含多个相关功能点。每完成一个功能点就记录，不等整项任务结束。

| 字段 | 内容 |

| 任务编号 | Txxx |

| 状态 | 待开始 |
| 创建日期 | YYYY-MM-DD |

## 2. 目标与主线关系

说明要解决的问题、完成后的实际行为，以及它如何推进对应里程碑。支撑任务说明支持作用，不计作业务里程碑完成。

## 3. 范围与功能点

明确本次包含和不包含的内容；新增范围在这里记录原因和授权依据。

| 功能点 | 计划行为与验收条件 | 状态 | 实际记录 |
|---|---|---|---|
| F01 | 填写可观察、可验证的结果 | 待开始 | 完成后填写对应日期和记录标题 |
| F02 | 按需要增减行 | 待开始 | 尚未实现 |

## 4. 实施步骤与验收

- [ ] 确认前置依赖和当前基线。
- [ ] 完成本次功能点，并及时记录。
- [ ] 执行与变更相匹配的验证；未执行项说明原因。
- [ ] 验收条件逐项核对，不把代码存在等同于验证通过。
- [ ] 补齐文件清单、遗留问题和接续步骤。
- [ ] 回写总文档。

补充本任务专属的业务验收条件；通用清单不能代替它们。

## 5. 开发记录

### YYYY-MM-DD / F01：功能点名称

- **当次状态：**进行中 / 待验证 / 已完成 / 受阻。
- **实际行为：**用户或调用方现在能观察到的变化。
- **实现与决策：**具体处理方式、选择原因、接口或数据变化。
- **修改文件：**相对路径链接与职责；计划中的文件不要写为已修改。
- **验证：**实际命令、执行目录、结果；Mock 与真实服务分别标明。
- **问题与处理：**遇到的原因、采取的处理、仍未解决的部分。
- **下一步：**可以直接继续执行的具体步骤。

同一天多个功能点分别记录；跨日追加新日期。更正历史结论时保留原日期并说明更正原因，不伪造历史完成日期。
