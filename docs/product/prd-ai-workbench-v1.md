## 1. 背景、问题与目标

### 1.1 用户和真实场景

用户有 5 年 Java 开发经验，正在学习 Python、RAG、LangChain 和 Agent 应用开发，使用 PyCharm 跟课程敲代码、在语雀记笔记，当前学习项目为 `D:\python\tiangong_agent`。学习材料包含本地课程及深造客户端课程，没有统一字幕。用户通常能听懂讲解，却难以独立组织实现步骤，容易遗忘零散知识。

求职准备覆盖 Java 后端、Python 后端兼 AI、Agent 应用开发，目前没有现成题库。用户希望借鉴 WorkBuddy 的工作区、任务、Agent、工具与成果组织方式，形成自己的 Windows 桌面工作台。文本大模型选 DeepSeek，允许云端处理，不依赖本机运行大模型。

### 1.2 要解决的问题

| 问题 | 产品应提供的帮助 | 不使用的替代指标 |
| --- | --- | --- |
| 跟着敲会，独立实现没思路 | 先解释输入输出、模块职责、执行顺序和边界，再做一个小练习 | 抄写行数、对话轮数 |
| 知识点琐碎，回顾时找不到 | 有来源的题目、笔记、回答与复习项相互关联 | 笔记篇数或总结长度 |
| 面试回答停在概念层 | 一次一题，基于原回答追问原理、取舍、异常及验证 | 背中固定参考措辞 |
| 工具分散，重复搬资料 | 共用资料、模型和任务记录，成果可继续进入题库及练习 | 首页入口数量 |
| 总结了仍然忘 | 先回忆再核对，保留提示使用和自评，回到具体卡点 | 一次回答就永久“掌握” |

### 1.3 产品目标

首版让用户完成一条可信流程：选择项目或笔记 → 生成一批候选训练题 → 检查并入库 → 完成文字或逐轮语音面试 → 查看有依据的反馈 → 加入复习 → 重开后接着练。

建议用真实试用检验价值：用户能不看课程，描述一个功能的调用顺序与设计理由，并完成或解释一个小改动；后续回顾时能返回原资料并重新讲清。此目标是产品验证方向，不在设计阶段声称已达到。

## 2. 决策、假设和范围

### 2.1 已确认条件

| 项目 | 已知结论 |
| --- | --- |
| 形态 | Windows 桌面应用，个人使用 |
| 整体体验 | 参考 WorkBuddy 的共用左侧导航，中央“办公 / 开发 / 设计” |
| 模型 | DeepSeek 文本模型；本机不部署大模型 |
| 云端 | 允许云端处理；任务仍须展示所选资料范围 |
| 首批应用 | 面试题整理 Agent、AI 面试官 Agent；再完善课程复盘 |
| 面试方向 | Java 后端、Python 后端兼 AI、Agent 应用开发 |
| 输入 | 面试支持文字与语音；课程视频无字幕的情况存在 |
| 底座 | 工作区、会话任务、Agent 配置、执行过程、模型与工具、成果保存六项 |
| 复盘节奏 | 10 分钟快速回顾，以及 20～30 分钟带小练习 |

### 2.2 本轮设计默认

| 决策 | 默认方案与原因 |
| --- | --- |
| 账号与空间 | 单用户、多工作区，无登录和团队权限系统，减少无关底座 |
| 初始体验 | 正式版题库为空，提供“主题生成候选题”引导；示例可单独体验，不能混入真实题库 |
| 建题 | 默认 10 道，1～30 道；生成草稿与保存入库分开 |
| 面试 | 默认训练模式、20 分钟、5 道主问题、每题最多 2 次追问；均为软目标 |
| 小批选题 | 手选少于默认题数时按可用题数开始，不用重复相同题目凑数 |
| 追问 | 最多次数为上限；信息足够时提前结束，不为凑轮数机械追问 |
| 反馈 | 训练每题结束后给反馈；模拟面试结束后统一给反馈 |
| 评分 | 首版报告优先呈现回答依据、遗漏和改进动作；不要求总分、雷达图或招聘通过率 |
| 语音 | 点击录制 → 停止 → 转写 → 编辑核对 → 主动提交；单次最多 3 分钟 |
| 工具 | 内置资料及题库工具 + 最小本地 stdio MCP，按 Agent 与任务共同约束范围 |
| 搜索 | 本地关键词、标签和筛选；首版不引入向量数据库 |
| 复习 | 手动启动、先回忆再核对；自评保留记录，不自动判定永久掌握 |
| 同时执行 | 一次最多一个主动 AI 执行，其余排队；等待用户不占执行槽 |
| 桌面尺寸 | 1280×800 起作为日常目标，重点验证 1536×1000；更窄时收缩导航、堆叠检查区 |

这些是设计完成所需的具体默认，可在实际试用后调整。模型具体 ID、框架版本及语音供应商在真实集成前核验，不以当前原型里的显示文字当作服务能力证明。

### 2.3 阶段范围

| 阶段 | 范围 | 完成条件 |
| --- | --- | --- |
| P0：首个可用版本 | 六项最小底座；候选题整理、文字和逐轮语音面试、报告、手动复习；Markdown/JSON 导出 | 本文第 8 节真实功能验收通过 |
| P1：学习复盘 | 课程目录、讲解转写、笔记与代码关联，快速回顾/小练习，语雀保存、复习提醒 | 先验证材料可得性与关联精度，再扩展输入 |
| P2：按需扩展 | Skills 管理、更多开发和设计助手、更多连接器及任务并行 | 有真实使用需求后分别定义 |

首版不包含通用电脑控制、自动执行学习项目代码、完整 Office 编辑器、自主 Agent 团队、公开插件市场、远程 MCP OAuth、团队协作、自动投递和对外消息发送。首页“开发 / 设计”属于分类和后续扩展入口；可选择内置模板创建任务，不因此承诺通用编程代理或设计生成能力。

### 2.4 WorkBuddy 借鉴边界

借鉴任务组织、资料范围、执行可见性、模型/工具设置和成果管理，业务逻辑自行实现。依据是已完成的 WorkBuddy 5.8.3 本地发布包静态分析，不代表当前线上账号能力已测，也没有完整恢复内部 CLI Agent 循环。详细证据见既有逆向报告；本 PRD 不依赖其账号、私有服务或运行时。

## 3. 用户故事与主流程

### 3.1 用户故事

| ID | 作为用户，我希望 | 收益 | 对应需求 |
| --- | --- | --- | --- |
| US01 | 选择一个项目和本次相关文件，而不是每次搬整个项目 | 上下文具体且范围可见 | FR01、FR02 |
| US02 | 没题库也能按岗位主题生成少量候选题 | 从零起步 | FR03 |
| US03 | 检查、修改和选择候选题后再保存 | 避免错误信息直接成为知识库 | FR03、FR04 |
| US04 | 练习时一次只面对一个问题，能回看自己的原话 | 减少背答案，练表达与思路 | FR05 |
| US05 | 语音技术名词识别不准时先修正转写 | 避免识别错误变成能力判断 | FR06 |
| US06 | 看到反馈对应哪句回答，而不是一个凭空分数 | 知道具体怎么改 | FR07 |
| US07 | 把卡住的问题带去复习，先独立回忆再看要点 | 分清熟悉和理解 | FR08 |
| US08 | 退出后找回题目、面试、成果和草稿 | 避免反复重来 | FR09 |
| US09 | 知道模型和工具正在做什么，失败后可恢复 | 可以控制执行过程 | FR10、FR11 |

### 3.2 首次使用

1. 打开首页；明确产品为个人本地资料工作台，可按任务使用云端能力。
2. 配置 DeepSeek 并执行不含项目资料的连接测试；未配置时可浏览和记笔记，开始 AI 任务时再提示配置。
3. 新建工作区、选择目录或粘贴笔记，看到实际所选范围与排除项。
4. 题库为空时从岗位/主题建立候选题；保存至少一题后可开始面试。
5. 未配置语音服务时文字面试可用，语音入口说明配置缺口，不让用户陷入录音后无法转写的流程。

### 3.3 资料到题库

选择资料/岗位/主题/数量 → 检查范围 → 执行与取消 → 候选题预览、编辑与查重 → 选择保存 → 查看题库来源 → 手选题进入面试。

通用任务的 Markdown 成果可“继续整理成题目”：复制一份成果快照作为输入，创建整理任务，生成结构化候选题后仍需检查保存。不得把任意 Markdown 直接当成已验证题库，也不改变原成果。

### 3.4 面试到复习

选方向与模式 → 固定本轮题目版本和参数 → 主问题 → 提交回答 → 必要追问 → 训练反馈或下一题 → 结束 → 报告 → 加入复习 → 回忆草稿 → 查看参考 → 自评与下一步。

用户可不知道、跳过或提前结束；这些都是正常分支。重新练习创建新面试，不覆盖旧回答。报告重开独立于活动面试，查看旧报告不切换当前答题进度。

## 4. 功能需求

### FR01 · 首页、导航与工作区

- 共用侧栏包含新建任务、助理、专家·技能·连接器、定时任务、资料库、更多；下方任务历史、空间和设置。
- 办公、开发、设计切换中间任务建议与提示，不改变全局导航。切换模块保留未提交任务草稿、附件和工作区选择。
- 工作区选择位于任务输入附近；支持无工作区创建主题任务。任务提交时锁定所选范围快照，后续首页切换不改变旧任务。
- 支持创建/重命名工作区、关联目录、移除关联；移除不删除原项目。正式版工作区真实隔离，不沿用原型中两个示例空间的共用材料池。
- 首页模型、语音和工具状态可见；通用任务进入任务工作台，有目标、状态、对话和检查区。

### FR02 · 资料库与来源

- P0 支持粘贴文本、MD/TXT/JSON 及 Python/Java 等源码文本。目录只读选择文件，默认排除凭据、依赖、缓存和二进制。
- 材料显示名称、类型、来源、读取状态与当前选择；预览与“选入任务”分开，查看材料不意味着发送给模型。
- 来源字段保留路径或 URL、内容指纹、读取时间、定位依据、版本和可用状态。只在真实读取后显示引用行号，不编造代码路径或课程时间点。
- 文件失效或变化时标记待核对/不可用。新任务确认使用旧快照或重新读取；历史面试不被无声替换。
- 设计默认：单份文本不超过 200 KB、本次原始文本合计不超过 1 MB；超过时分批或缩小范围。发送前还按实际模型输入预算检查，不能因原始文件小就跳过上下文校验。
- 用户粘贴材料明确标为用户文本；课程跟写项目与实际工作经历分开，不把课程练习改写成生产经验。
- P0 文件预览不用执行项目代码。课程音视频、图片理解和语雀双向同步不在此版本材料解析范围。

### FR03 · 面试题整理 Agent

- 输入工作区、主岗位、主题、数量、建议难度、选定资料和补充目标；无资料也可生成主题训练题。
- 展示读取/归纳/生成/结构校验步骤。结果先是候选草稿；未通过字段校验不得保存为正式题。
- 每题包含题干、知识点、岗位标签、难度、考察意图、回答要点、合理方案、追问方向和来源。答案允许多个合理方案。
- 来源类型区分模型训练题、项目衍生题、用户资料题、已核验外部资料题；没有外部核验不能标公司真题。
- 明确重复按规范化题干提示；近似主题只建议比较，不能自动合并不同考察角度。
- 可编辑、取消选择并部分入库；保存显示新增/更新/跳过结果，操作 ID 确保重复点击和重试不产生重复题。
- 更改资料范围创建新任务或新版本，不在同一执行中无提示替换输入。

### FR04 · 题库管理

- 提供岗位、知识主题、难度、来源、复习状态筛选及关键词搜索；筛选空态与详情一致，不展示筛选外旧题来伪装结果。
- 详情显示题目、意图、要点、追问与来源，允许修订。保存生成新版本，旧面试仍引用旧版。
- 选择题目后开始面试，题目不足时降低本轮题数或先补题；不能静默重复凑数。
- 支持手动加入/移除复习、归档和 JSON 导出。归档题不进入新面试；历史题目快照不删除。
- P0 不提供自动爬面经，用户主动提供来源时可作为资料处理。

### FR05 · AI 面试官

- 参数包含主方向、模式、文字/语音、软时长、主问题范围及追问上限。开始后保存快照，修改默认设置不改变当前轮次。
- 一次展示一个问题。提交前可修改，提交后形成不可原地改写的回答记录；更正以追加说明保留。
- 追问引用实际回答，关注原理、执行边界、异常、工程取舍和验证；不能声称用户说过其未提及的内容。
- 训练模式有逐级提示，提示使用与每次回答关联；模拟模式不主动展示答案，用户请求提示时说明会留下辅助记录。
- 提交期间禁用重复提交，失败保留输入；跳过、不知道、提前结束单独记录。
- 进度按主问题完成情况展示；追问不虚增主问题数量。软目标到达时提示可以结束或继续，不截断输入。
- 同一时刻只有当前面试接受回答；浏览资料或报告不自动结束面试。

### FR06 · 逐轮语音

- 先检查服务配置，用户点击后请求麦克风；可见录音状态、时长和停止按钮。默认最多 3 分钟，停止后不自动提交。
- 录音/停止/转写/待核对/提交是不同状态；上传只发生在明确开始的语音处理流程，不能持续后台监听。
- 转写可编辑，技术名词可修正。确认后与文字走同一答题流程，记录输入来源为语音转写。
- 识别失败可重试或切换文字；重试不重复创建回答。切文字保留已有文本，丢弃未保存录音前提示。
- 原音频属于本机附件，用户可删除；删除原音频不删除已确认文字。首版默认不自动永久保留云端中间下载件。
- 只按已确认文字反馈，不在没有音频分析的情况下评价语速、情绪、发音或人格。

### FR07 · 报告与成果

- 报告显示方向、模式、完成状态、回答/提示/跳过统计、逐题原回答、参考方向、具体反馈及下一步动作。
- 每个“正确/遗漏/需要核对”结论应能指回实际回答或来源；证据不足标记不足，不给伪精确等级。P0 默认不输出总分。
- 原回答与生成反馈分区，用户复盘笔记独立保存。编辑题库不改历史问题；报告重生成保留新版本。
- 支持保存、搜索和重新打开报告，导出 Markdown；导出包括原回答、提示和反馈依据，排除密钥、内部日志和非本轮材料。
- 通用任务成果提供安全 Markdown 预览与编辑，明确保存；续聊生成修订稿时先比较，不能覆盖用户手动修改。
- 原型报告目前为固定示例反馈，且不输出评分；报告归档、笔记和原回答保存是实际浏览器交互。

### FR08 · 手动复习与回忆

- 题目详情和报告可加入复习，按题目关联去重；只记录用户选择，不依据固定样例自动判定真实薄弱程度。
- 列表显示来源、题目、最近练习及是否借助参考；提供全部、未练与有记录筛选。
- “开始回忆”先隐藏答案，草稿自动本地保存；展开参考明确标记辅助。重新打开同一未完成草稿不能抹去看过参考的事实。
- 用户选择“仍需补练”或“能讲清楚”，保存本次内容、自评、是否辅助和时间；自评不替代客观掌握判断。
- 练过不自动移除；可开始单题面试或下次再练。先只做手动复习，不伪装已开启后台提醒。
- 20～30 分钟小练习在 P0 可作为建议说明；真实课程驱动的个性化练习、提交代码验证属于 P1。

### FR09 · 任务、保存、取消和恢复

- 任务状态为 `draft / queued / running / waiting_user / completed / failed / cancelling / cancelled / interrupted`。UI 根据服务事件展示，不靠提示词变更状态。
- 等待用户检查候选题、回答问题、核对转写都属于等待用户，不显示模型持续思考。
- 取消传播到模型、转写和工具；不能中止远端请求时说明本机已停止接收，费用可能已产生。迟到结果不得写入题库、覆盖成果或推进阶段。
- 失败显示当前步骤、可恢复输入和错误原因。已完成保存不重复执行；副作用结果不明先查状态。
- 重开后恢复已保存题库/任务/报告，活动执行标记中断；用户选择继续，不自动重发上一次请求。
- 草稿在输入停止后 800 ms 内尝试保存，页面切换前刷新保存；只有写入确认才显示已保存。存储失败保持未保存标记和可复制内容。

### FR10 · 模型与配置

- DeepSeek 默认文本供应商。保存接口地址、模型 ID、超时和非敏感配置；密钥由系统安全存储管理，界面只显示已配/未配。
- 连接测试使用无项目资料的最小请求，显示测试中、成功、失败及可读错误；配置失败不清空任务。
- 语音服务独立配置和状态，不假定 DeepSeek 文本接口兼任转写。没有语音供应商不影响文字流程。
- 默认参数只影响新任务；正在运行的任务和面试保持参数快照。
- 数据管理允许导出、删除本机记录并说明范围，不把清理本机解释为清理外部供应商的留存。

### FR11 · Agent、工具与 MCP

- 首版两个内置 Agent，共用模型、资料和题库。自定义 Agent 可设名称、任务说明、模型引用和允许工具，保存配置版本。
- 自定义提示词不能绕过内置面试的提交规则，也不能扩大资料或工具权限。
- 权限取交集：服务已连接且工具启用、Agent 允许、本次任务范围和动作授权均满足才执行。工具名称本身不能证明只读或无副作用。
- MCP 最小支持用户主动配置本地 stdio 可执行文件、参数与环境变量引用；参数数组启动，不默认拼成 Shell 指令。
- 展示连接、工具列表、允许开关、调用输入摘要、输出/错误、时间和取消状态；缺连接或越界明确阻断。
- 内置建题及文字面试不依赖额外 MCP 服务。服务崩溃仅影响依赖它的任务，退出只清理本工作台拥有的进程。
- 工具结果按外部数据处理，不能作为修改系统规则或授权的依据。执行轨迹展示事实摘要，不展示模型内部思维链。

## 5. 界面设计与状态

### 5.1 稳定的信息架构

```text
共用侧栏
  新建任务 → 办公 / 开发 / 设计 → 任务工作台
  助理 → 面试题整理 / AI 面试官
  专家·技能·连接器 → Agent 配置 / 工具设置
  定时任务 → 后续能力说明
  资料库 → 空间、材料选择和来源预览
  更多 → 题库 / 面试 / 复习 / 报告
  任务记录、空间列表、设置

核心任务
  资料 → 候选题 → 题库 → 面试 → 报告 → 复习 → 再练
  通用成果 → 快照作为新整理任务的材料
```

宽屏任务页采用对话与右侧“执行步骤 / 参考资料 / 成果”；面试页优先当前题与答题区；报告将原回答和参考方向并置。窄屏保留同一导航模型，右侧区域上下排列。具体屏幕、组件、断点、截图和状态见 UI 文档。

### 5.2 必须定义的状态

| 场景 | 空态 / 初始态 | 处理中 | 失败 / 恢复 |
| --- | --- | --- | --- |
| 资料 | 无关联，添加文本或目录 | 读取、检查大小与范围 | 缺失/过期，重新关联或保留旧快照 |
| 题库 | 无题，引导生成 | 整理进度与取消 | 格式错误不入库，重试或手动编辑 |
| 面试 | 无题或未配模型 | 等待回答/提交/追问 | 保留输入，恢复当前已确认轮次 |
| 语音 | 未配/未授权 | 录音、转写 | 停止、重试或切文字，不丢原文 |
| 成果 | 没有可预览结果 | 生成草稿、保存 | 未保存标记，不显示假成功 |
| 工具 | 未连接/工具被禁 | 连接、调用与取消 | 超时、越界、崩溃，说明影响范围 |
| 复习 | 无复习项 | 回忆与核对 | 草稿留存，自评可重新练 |

## 6. 数据、服务边界和可靠性

### 6.1 逻辑职责

桌面负责交互；本地服务负责状态、权限、SQLite 和附件；模型与语音适配器负责外部请求；内置工具和 MCP 走同一校验入口。技术方案选择一条桌面到本地服务通信方式，避免为了复刻 WorkBuddy 而复制全部进程层级。

| 数据 | 必要字段与约束 |
| --- | --- |
| Workspace | 稳定 ID、名称、目录关联、岗位标签；不含原项目所有权变更 |
| MaterialVersion | 来源、内容指纹、读取时间、范围、定位信息；旧快照不可原地替换 |
| AgentConfigVersion | 提示词、模型引用、允许工具、版本；任务保存所用版本 |
| Task / Event | 状态、步骤、范围快照、错误、事件序号、取消及恢复位置 |
| QuestionVersion | 题干、主题、岗位、要点、追问、来源、修订 |
| Interview / Turn | 参数快照、题目版本、提交 ID、原回答、状态、提示与输入方式 |
| ReportVersion | 回答引用、生成反馈、用户笔记、版本；用户笔记不与原回答混写 |
| Review / Attempt | 题目、来源报告、草稿、是否辅助、自评、时间；唯一复习项，多次练习 |
| Artifact | 内容版本、任务引用、用户编辑与保存状态 |
| Provider / Attachment | 非敏感配置、系统密钥引用、本地音频与导出文件位置 |

### 6.2 可靠性规则

- 回答提交、候选入库、报告保存使用操作 ID 和事务。重复请求返回同一次结果，不双写。
- 题目和材料被归档时历史快照仍可读；失败不能回退已确认回答。
- 流式结果按任务 ID、轮次和事件序号应用；取消或旧轮次的事件不得推进当前任务。
- 本地数据库迁移前备份；备份恢复入口只覆盖工作台数据，不改用户项目。
- 内容预览按纯文本/受限 Markdown 渲染，禁止将材料当脚本执行；导出排除密钥。
- 断网可浏览、编辑本地笔记、题库与报告；生成、追问和转写按需提示网络依赖。
- 错误日志保留步骤和错误码，过滤凭据；不默认写全量源码、录音和原始模型请求。

### 6.3 非功能验收目标

这些是实施目标，不是当前原型的实测性能结论：

- 常规本地导航在 300 ms 内给出可见反馈；长操作先进入状态，不等待完成才响应。
- 对话提交和录音开始/停止立即显示本地状态；模型耗时以实际服务表现展示，不承诺固定秒数。
- 以 10,000 道本地题目做关键词检索时目标 P95 不超过 500 ms，测试环境和样本随结果记录。
- 首版以普通 Windows 笔记本验证，不要求 GPU 或本地大模型。
- 主要动作有键盘焦点和可读标签，状态不只用颜色，尊重减少动态效果设置。
- 1280×800、1536×1000 和系统缩放下主要操作可达；390px 是原型响应性压力检查，不等于承诺发布手机客户端。

## 7. 后续学习复盘路线

P1 保留用户最初需求，不让面试模块吞掉学习目标：

1. 按课程目录建立课次，记录本节目标、用户笔记、老师源码与跟写代码。
2. 优先导入可获得的文字、课件和源码；对讲解建立带时间的转写，再由用户核对关联。
3. 10 分钟模式聚焦本节目标、3～5 个重点、用户自己的解释和一个卡点；20～30 分钟增加最小改动与验证。
4. 逐级提示先问思路，再给定位与骨架，最后才给参考，保留用户尝试。
5. 结果可转候选面试题或复习项；语雀写入先预览，明确目标知识库和新增/更新规则，保留本机副本。

已知限制：深造播放器短片段讲解音频取得且用户试听清楚，窗口画面测试为黑屏，未恢复视频内容，也未验证整节课同步。音频相对时间不等于课程视频位置；暂停、拖动、倍速不能简单线性换算。后续先验证课程方可提供的独立课件/源码和文字关联，不承诺绕过播放器限制或已解决音画对齐。

## 8. 验收标准

“原型可点”与“真实功能完成”分开。下面是正式产品的可测试验收，不因前端模拟通过而勾选完成。

| 编号 | Given / When / Then |
| --- | --- |
| AC01 | 给定空工作区，选择目录与文件后，预览显示实际内容；开始任务的请求仅含已选且可读材料，排除项不被发送。 |
| AC02 | 给定缺失/失效密钥，连接测试显示具体错误且保留任务；有效配置的最小请求成功，日志/导出不出现密钥。 |
| AC03 | 给定空题库，按主题生成 10 道候选，修改并只选 5 道保存；入库正好 5 道，重复点击不增加重复记录。 |
| AC04 | 给定格式不完整和相似候选，显示字段错误/比较提示；未通过校验不能直接保存，近似题不自动删除。 |
| AC05 | 给定已保存题，组合岗位/主题/来源筛选和搜索后列表及详情一致；零结果不展示旧详情。 |
| AC06 | 给定手选 1 道题，开始单题练习只安排 1 道主问题；修改全局默认不会改变已开始轮次。 |
| AC07 | 给定一个文字回答，后续追问能指出依据；提交两次只留一条回答，失败时输入仍在。 |
| AC08 | 给定训练和模拟两种模式，训练逐题结束反馈，模拟结束后反馈；提示、跳过和不知道分别保留。 |
| AC09 | 给定语音服务配置，点击录制后状态可见；停止后转写可改，主动提交才成回答，最长 3 分钟不自动提交。 |
| AC10 | 给定麦克风拒绝、转写失败或断网，可重试/切文字；已确认回答与文本草稿不丢失。 |
| AC11 | 给定已完成面试，报告引用真实回答/来源，无依据则标不足；没有总分也能解释每个建议从何而来。 |
| AC12 | 给定旧报告和后来修订的题目，打开旧报告仍为原问题/回答；笔记保存及报告重生成不覆盖原文或旧版本。 |
| AC13 | 给定从报告加入复习，去重且关联原题；回忆先不显示参考，看过参考后重开草稿仍记录辅助。 |
| AC14 | 给定一次自评，练习内容/辅助/时间写入；不自动移除或标永久掌握，可再次练习。 |
| AC15 | 给定运行中的模型/工具，取消后迟到事件不入库、不推进面试、不覆盖成果；显示实际停止状态。 |
| AC16 | 给定断电/退出中的任务，重开显示中断和检查点；用户继续后不重复提交已确认回答或副作用。 |
| AC17 | 给定 stdio 测试服务，能连接、列工具及执行允许项；禁用工具/越界路径在执行前阻断，超时可观察。 |
| AC18 | 给定自定义 Agent，创建/修订模型及工具范围后新任务使用该版本；不能改内置面试状态或扩大任务访问。 |
| AC19 | 给定存储写入失败，不显示保存成功；保留未保存状态和可复制内容，恢复后可重试。 |
| AC20 | 给定成果编辑后续聊，修订以新稿对比；交给建题时用快照，不静默解析/覆盖原成果。 |
| AC21 | 给定 Markdown/JSON 导出，原回答/提示/来源和题目字段可核对，密钥与非本轮资料不在文件内。 |
| AC22 | 给定 1280×800、1536×1000 与系统缩放，主要按钮和检查区可达，无破坏性溢出；键盘可完成核心操作。 |
| AC23 | 给定断网，本地题库/笔记/报告仍可看和改；依赖云端的动作说明原因且保留输入。 |
| AC24 | 完成端到端切片：选材料 → 生成 10 道 → 保存至少 5 道 → 文字及语音面试 → 报告 → 复习 → 重开继续，证据来自真实服务或注明的可控测试替身。 |

自动化重点是状态、幂等、范围、保存恢复；语音准确性、反馈是否贴合回答及练习价值需小样本人工核对。不得修改学习项目代码来伪造练习结果。
