> 日期：2026-10-19（Asia/Shanghai）。
> 状态：两轮评审与综合方案已完成，待用户审阅采纳；本文件不是已批准的新 PRD。
> 参与：协调者 Codex、用户指定的 Claude Code、OpenCode；通过真实 Orca 会话执行独立审查与交叉讨论。
> 基线：[PRD v1.0](prd-ai-workbench-v1.md)、[需求探索记录](2026-10-18-learning-workbench-discovery.md)、[技术方案](../technical/technical-design-v1.md)、[接手指南](../development/agent-onboarding.md)及当前任务台账；代码快照 `dda7374`。
> 原 PRD、技术方案和业务代码不作修改；下面的优先级、阶段调整和新增验收均是推荐，不能据此将现有承诺宣布取消或视为开发完成。

## 1. 推荐结论

保留“共用工作台 + 面试准备优先 + 后续课程复盘”的产品方向，以及已经实现的 Electron/React/Python/SQLite 基础。优化应集中于三件事：**尽早验证模型是否真的帮到练习；把功能通过、内容可信与真实服务验收分开；明确用户能控制的资料、费用、恢复和数据范围。**

不推荐重写架构，也不推荐为缩短首版而直接删除语音、Agent 配置、共用工作台或当前 MCP 基线。可以增加内部试用检查点，但完整 P0 仍按既有范围收口。若要更改正式交付范围或 M1 门禁，必须另行记录用户采纳的决定并同步计划。

### 已有设计值得保留

- 候选生成与正式入库分开，允许人工编辑、部分保存和重复检查。
- 真实工作经历、课程练习、用户资料和模型训练题分型，不能编造公司真题或生产履历。
- 一次一题，原回答不可原地改写；逐轮语音先核对文字再提交。
- 报告不强制总分，参考答案允许合理替代，复习先回忆再看参考。
- 版本快照、操作 ID、run 栅栏、事件序号、提交后 ACK、显式恢复和离线输入保护。
- 不引入向量库、通用多 Agent 框架、远程业务服务或自动执行学习项目代码。

## 3. 建议如何改 PRD 条款

### 3.1 价值目标：练习有帮助，不等于模型给了更高评价

建议将 §1.3 分为：

> **P0 面试价值假设：**用户能从一次真实练习中找到具体表达或理解卡点，定位到原回答与参考材料，选择一个改进行动；后续练习能够重新独立解释，并用改变条件或不同角度的问题检查理解。
> **P1 学习价值假设：**用户能够脱离课程解释模块职责、调用顺序和取舍，并完成或解释一个小改动，保留现有学习目标。

最小产品补充：题目详情能打开历次回答与报告，复习项保留本次练习卡点和来源链接。先复用现有题目、面试、报告、复习的数据关系，不建设独立能力画像或自动知识图谱。

试用时记录：题目与版本、是否借助参考、原卡点、具体下一步、重练或换角度题的回答、操作者自评与人工复核意见。可以由同一用户完成；不能让生成反馈的模型自评通过就代表学习提升，也不能把“同题 gaps 变少”直接等同理解改善。没有足够试用前不承诺效果百分比或招聘结果。

### 3.2 内容可信：三个维度分别展示

| 维度 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| 保存状态 | 候选/已入库/已归档，用户如何组织记录 | 入库不代表事实正确 |
| 来源类型与定位 | 模型训练题/项目衍生/用户材料/已核验外部来源；引用的版本和原文确实存在 | 原文存在不代表支持模型结论，更不代表原文本身正确 |
| 核对记录 | 未人工核对、用户已检查，以及可选的外部核验记录与时间 | 用户检查不等于权威认证；模型不能自行把来源升级为 verified_external |

以上是建议的最小语义，不要求本轮实现三套复杂状态机。可复用现有 provenance 和审核记录，以标签/元数据表达。外部来源核验要有实际来源与人工记录；主题生成无资料时必须明确为模型训练题。

反馈和报告至少区分：引用到的事实、模型解释、待核对点、用户笔记。评价“遗漏”前先说明本题考察点，接受语义相同和其他合理方案；找不到支持的判断降为“待核对”，不编造依据。用户标记争议不覆盖原回答或旧报告，保存更正笔记或新反馈版本。

### 3.3 质量验证：最小可执行样本清单

在首次真实模型样本中覆盖以下回答情形，而不是只测试一条顺利回答：

- 正常但简短；包含同义表达或不同合理方案。
- 明确错误、信息不足或前后矛盾。
- 不知道、跳过，或引用用户没有说过的内容。
- 课程练习与真实工作项目分别提供，检查是否虚构职责和生产指标。

每条判断人工检查：题目可回答且考察点一致；引用存在且语义支持；追问贴合且不过度重复；改进建议可以执行；不会把唯一参考措辞当标准答案。争议项记录，不用“95%准确”“双盲评”等未经测算的门槛装饰单人产品。后续扩大样本再决定量化指标。

真实 ASR 可在 M2 期间先做候选供应商小样本探查，沿用 M3 已有技术词样本验收要求；不因提前探查自动开通账号、购买服务、采集麦克风或上传私人课程。供应商接口、价格和留存政策到实际集成时重新核验，本轮无外部实测。

### 3.4 材料与云端：提交前说明实际会发送什么

建议补入 FR02/FR10：

> 导入限制是文件可被保存/预览的上限，发送限制是本次模型请求可接收的预算。导入成功不代表资料全部可一次发送，也不代表资料已经上传。开始任务前显示所选来源、版本、范围、目标供应商/模型、预算估计和调用计划；用户启动该任务即授权本次显示范围，无需每次内部只读步骤再次弹窗。材料、目标或副作用范围变化时重新确认。

- 超预算时提供取消、减少文件、改用用户明确粘贴的片段或已定义的显式分批流程。不能把“分批”当自动解决所有跨文件问题；任务间上下文不完整时要说明。
- 行范围选择可作为后续便利功能，不强制引入编辑器才允许 M1 交付；最小版本应保证至少有一条可操作的缩小范围路径。
- 不后台静默截断、自动读取整个关联目录或把未核对摘要替换原始输入。
- 在预算展示中区分估计 token 与实际 usage；没有核验价格就显示费用未知，取消不承诺远端零费用。
- 语音按钮明确“停止后上传至所选服务转写”或采用显式转写按钮，保留本轮选择；停止不等于提交回答，排队上传可取消。
- 工具输出、相关题目、已确认回答也可能进入模型上下文。摘要需说明这些类别，不能只列材料文件名就声称覆盖全部发送内容。

### 3.5 恢复、备份与删除：沿用机制，补用户动作

| 状态/动作 | 建议产品语义 |
| --- | --- |
| queued/running/cancelling 后服务重启 | 沿用 T005 转 interrupted；保留输入和检查点，显示“未自动重发”。当前实现按用户点击恢复的顺序重新入队，不承诺自动保留旧排队顺序 |
| waiting_user 重启 | 保留候选检查/答题/转写核对等具体等待原因，打开对应页面继续，不能重跑此前模型步骤 |
| 已提交回答后模型失败 | 原回答仍已保存；仅重试缺失追问/反馈，不重复写回答 |
| 只读记录与草稿 | 已保存与未确认缓冲分开显示；存储失败仍可复制，不用自动重启掩盖写失败 |
| 导出 | 用户所选业务对象的可读交换格式，不承诺可以恢复完整工作台 |
| 完整备份/迁移备份 | 明确 DB-only 或包含附件，清单、哈希和 schema 可核验；密钥不进入备份，恢复后重新配置 |
| 恢复 | 显示替换范围，备份当前数据，停止执行/录音并校验包；不修改关联项目 |
| 归档/删除 | 归档保留历史；删除展示依赖、附件及应用管理备份影响，用户选择范围后执行并逐项反馈失败 |

不新增默认自动恢复或批量恢复作为必要门槛。删除范围限于应用拥有的记录和文件；用户另存导出、供应商留存、Windows/SSD 残留不在此保证内，不以扫描不到字符串宣称安全擦除。

对于 waiting_user，后续技术方案应补“等待原因 → 用户动作 → 校验 → 状态”的映射表，分别覆盖候选入库、提交回答、核对转写、成果确认与工具批准。不能把所有等待状态都简单地用通用 continue 重跑上一模型调用。

### 3.6 通用任务与工具：用一个真实场景限定深度

建议补一条用户故事：

> 作为准备面试的用户，我可以把自己粘贴的项目说明或岗位要求交给一个可配置的整理 Agent，预览并编辑 Markdown 成果，再显式把该成果快照交给建题流程；原成果和历史版本不被覆盖。

这只是对既有成果交接能力的用途说明，不意味着新建招聘系统、简历解析器或通用电脑控制。求职背景可先通过现有资料/补充目标输入，目标职级允许“未定”，不因 5 年 Java 年限推定 AI 资历。

成果修订先保存新稿并可并排查看，不强制逐段自动合并。MCP 保留当前方案；权限采用现有交集和具体授权：目标、参数、配置或风险超出授权才重新确认。对未知副作用结果，先查实际状态，不自动重放。配置页明确本地 stdio 程序通常拥有当前用户权限，工具参数校验不等于隔离任意恶意程序。

## 4. 推荐交付顺序与门禁

以下是对现有计划的增补建议，尚未替换 [M1](../superpowers/plans/2026-10-18-ai-workbench-m1-plan.md)/[M2](../superpowers/plans/2026-10-18-ai-workbench-m2-plan.md)/[M3](../superpowers/plans/2026-10-18-ai-workbench-m3-plan.md) 的正式退出条件。

| 节点 | 具体交付 | 证据与限制 |
| --- | --- | --- |
| R0 文档口径修正 | 追问软硬限制、AC24 证据分层、决策沿革、动态能力说明 | 不推进业务里程碑，不让文档整顿长期阻塞已有安全开发 |
| E1 早期模型与发行风险探查 | 经用户配置后，用无项目资料主题验证候选/追问质量；一次最小 Python onedir + 资源 + stdio 握手探针 | 不等于公开业务入口或正式发行。未配置时标待验证，不伪造成功 |
| M1 真实建题 | 按现有 Task 04～09 补资料、配置、候选、题库、草稿与端到端接线 | 保留资料安全和幂等机制；真实 DeepSeek 样本与替身回归分别记录 |
| M2a 内部训练试用点 | 单题文字训练 → 针对性追问 → 可重开的最小报告 | 从现有 M2 切片中形成，不标 M2 或 P0 完成；输入保存和取消机制不能省略 |
| M2 文字闭环 | 训练/模拟、版本报告、手动复习、恢复、成果交接 | 人工质量清单与一次真实使用记录；价值结论由用户判断 |
| M3 完整 P0 | 语音、当前 MCP/Agent 基线、完整回归与发行 | 真实文本/语音、可信本地 MCP、干净 Windows x64 安装、备份恢复/进程清理证据齐全 |
| M4/P1 学习复盘 | 合法可得课程材料、讲解转写、来源关联与练习 | 课程原画面黑屏/时间映射仍是未解决输入条件，不冒充视频理解 |

**打包争议的推荐处理：**早期保留最小发行风险探查，完整干净机验证是 P0 必需门禁。现有 M1 Task 09 已要求无开发环境启动，若用户希望 M1/M2 内部试用不被此阻塞，应显式把“内部试用可继续”和“正式 M1 验收未过”分开；如要把该门禁正式后移到 M3，需更新计划并记录采纳决定，不能用本建议自动豁免。

**不推荐立即重排完整 M1 依赖：**“无资料主题样本可先验证”与“Task 05～07 可完全绕过 Task 04”不是同一结论。后者尚未通过接口与迁移依赖评估，不能作为已证实方案。

## 5. 建议补充的验收条款

编号采用本报告前缀 `OPT`，正式采纳后再映射原 AC，避免与现有编号冲突。

| 建议编号 | Given / When / Then | 验证方式 |
| --- | --- | --- |
