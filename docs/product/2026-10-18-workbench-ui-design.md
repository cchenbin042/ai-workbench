# 知序 · UI 页面与交互设计 v1.0

日期：2026-10-18（Asia/Shanghai）  
状态：本轮界面与交互设计交付完成，沿用用户已确认的 WorkBuddy 风格布局。

配套：[PRD](prd-ai-workbench-v1.md) · [需求覆盖与实现差距](2026-10-18-design-coverage.md) · [原型体验说明](../../prototypes/workbench-ui/README.md)

本文说明屏幕结构、主要动作、状态和页面交接。“原型已支持”表示浏览器内的交互；“正式版要求”表示待开发的产品规则。所有云端生成、语音转写和 MCP 结果仍是演示；未读取真实项目。

## 1. 统一布局

### 1.1 稳定的导航与任务上下文

- 侧栏是全局入口：新建任务、助理、专家·技能·连接器、定时任务、资料库、更多；任务历史与空间列表在下方，设置与账户在底部。
- 首页中央提供“办公 / 开发 / 设计”分段切换。它们改变建议任务、快捷项和输入提示，不创建三套互不相通的应用。
- 工作区放在任务输入区下方，与访问方式相邻；模型在输入区内。用户先知道这次要用哪些资料，再开始执行。
- 不恢复顶部“个人成长工作区”大卡。当前空间只是任务上下文，产品主体仍是共用工作台。
- 深入任务后，顶部保留模块与当前页面；任务标题、状态、模型和来源在内容区，不与全局品牌争层级。

### 1.2 内容区的四种骨架

| 骨架 | 适用页面 | 主要关系 |
| --- | --- | --- |
| 居中任务入口 | 首页 | 模块 → 快捷任务 → 大输入框 → 建议任务 |
| 主工作区 + 检查区 | 通用任务、建题、题库 | 中间专注当前动作，旁边核对步骤、范围或成果 |
| 问题 + 输入 + 辅助栏 | 面试、回忆 | 当前问题优先，进度/已回答内容/来源辅助 |
| 总览 + 证据 + 下一步 | 报告 | 先看本次记录，再对照原话，最后选择一个补练动作 |

侧栏、任务输入和检查区相互独立。查看资料、切换页签或收起右栏不视作提交，也不丢弃编辑内容。

## 2. 视觉与组件约定

### 2.1 当前视觉基线

| 项目 | 当前用法 |
| --- | --- |
| 主背景 | 炭灰 `#151515`，侧栏/基础面板 `#202020` |
| 主文字 / 次级文字 | `#eaeaea` / `#979797`；来源说明降低层级，不能仅靠浅色表达状态 |
| 分隔与边框 | 基础 `#353535`；结果/来源面板辅以暖灰边框 |
| 主要动作 | 低饱和暖沙色，典型 `#cbb092`；只用于当前关键动作和成果关联 |
| 来源/报告底色 | `#211f1c`、`#25211b` 一类暖深色，与对话底色区分 |
| 状态 | 完成淡绿、待核对暖棕、失败红褐，同时显示文字/图标 |
| 字体 | 系统 Segoe UI / 微软雅黑；路径与代码用 Consolas；少量报告数字用 Georgia |
| 图标 | 统一线性 SVG，语义稳定，无外部字体或图标网络依赖 |
| 间距 | 主要区块约 20～32px，组件内部约 12～20px；相关信息更紧、不同任务分区更松 |
| 圆角 | 基础面板约 10～12px；输入区和首页切换器可更圆，避免所有内容都做装饰卡片 |

原型使用桌面紧凑字号，正文/来源存在 10～14px 的不同层级，部分标签更小。这是当前呈现记录，不能视作正式可读性验收。桌面实施时仍需在 100%/125%/150% 缩放下检查中文正文、输入、来源和状态的可读性，必要时调整字号与密度。

### 2.2 组件行为

- 主按钮每个动作区只突出下一步；保存、生成和提交是不同动作。
- Chip 用于主题、多选或筛选，不用作隐藏的自动提交。选中状态有文字或勾选。
- Badge 区分示例、草稿、已保存、待核对、训练模式等；示例状态贴近内容。
- 路径及来源长文本允许断行；代码预览保持可复制、可滚动，不压缩到不可读。
- 成果支持预览/编辑；用户修改与模型建议分开。提示消息补充结果，不能代替错误位置和未保存标记。
- 对话中展示计划、已执行步骤和结果摘要，不展示模型内部思维链。

## 4. UI01 · 首页

保留“知序，和你一起完成。”中心标题。标题下为办公/开发/设计切换器、当前模块说明。输入框上方是与模块对应的常用任务，下面是两列建议任务。

输入框包含任务文字、资料附件、模型、语音入口和发送；下沿选择工作区与只读/修改前确认。当前原型仅保存任务和上下文示例，不实施文件访问权限。

- 切模块：保留未提交文字、附件和空间，更新提示与建议。
- 点建议：填入明确目标或进入对应流程；不在用户输入前悄悄运行。
- 发任务：非空目标创建任务；提交时保存上下文快照，进入任务工作台。
- 添加上下文：当前从示例文件选择，不能误称真实文件已导入。
- 个人学习、面试和项目理解作为办公/开发中的任务，不再作为一套特殊全局导航。

正式版空状态：未配模型仍能浏览与记笔记，开始云端任务时再引导配置；无空间也可做主题建题。开发/设计推荐内容不代表首版已具备任意编程或设计执行能力。

## 5. UI02 · 任务工作台

### 5.1 页面结构

任务头部显示模块、标题、状态、模型和空间。左中部为用户目标、附加资料、助手说明、处理计划和成果卡；底部补充要求。右侧是“执行步骤 / 参考资料 / 成果”检查区，可收起。

执行步骤按输入范围、处理摘要、结果和状态展开。参考资料显示任务提交时的范围。成果有 Markdown 预览、编辑、保存和“进入题库整理”。

### 5.2 动作与状态

| 动作 | 原型交互 | 正式产品规则 |
| --- | --- | --- |
| 开始 | 等待开始 → 确定性步骤演示 | 本地任务服务发起实际请求 |
| 取消 | 停止演示，保留已有记录 | 传播取消，丢弃迟到事件，说明远端实际状态 |
| 失败重试 | 可模拟失败，从当前步骤重试 | 查询副作用状态后重试，操作 ID 防双写 |
| 编辑成果 | 页签切换保留输入，明确保存后本地留存 | 事务和版本；存储失败不能提示成功 |
| 继续对话 | 追加补充记录，保留手动编辑稿 | 新建议做修订/比较，不直接覆盖 |
| 转为候选题 | 复制当前成果文字到新建题范围 | 将快照作为材料，真实模型生成结构化候选，仍需检查 |
| 刷新 | 活动任务标中断，由用户继续 | 按检查点恢复，不自动重复执行 |

当前“转为候选题”交接保存输入快照，候选内容仍来自内置样例，没有把 Markdown 真正解析成题目。

## 6. UI03 · 资料库

顶部项目条显示关联名称、路径与只读状态，右上操作是编辑关联和添加文本笔记。下方左列材料、右列内容和来源预览；底部把所选材料送入整理流程。

- 材料行：选择框、类型、名称、来源、可用状态。点击行查看内容与勾选材料是两个动作。
- 筛选：全部、我的笔记、待核对。当前待核对示例不能选入新任务。
- 预览：内容、来源位置、内容依据和本次任务使用说明；示例源码不显示成真实读取结果。
- 添加笔记：标题必填，原型上限 80 字符；内容必填，上限 20,000 字符。保存后选中，可刷新找回。
- 交接：建题范围显示选中材料名称，使用内容快照，避免后来选材改变正在检查的输入。

原型路径对话框只修改显示关联，不读磁盘；两个示例空间仍共用一个材料池。正式版需实现目录读取、隔离、版本、排除项、大小与模型预算检查。PRD 的 200KB/1MB 是正式设计默认，不能视作当前输入控件已按字节验证。

空态与失效态正式规则：无资料可添加笔记或继续主题建题；缺失文件显示原因，旧版本是否可用需明确选择，不静默混用。

## 7. UI04 · 题库整理 Agent

三步结构：①设定范围 ②整理与生成 ③检查并保存。

### 范围页

左侧依次为主岗位、知识主题、数量、建议难度、所选材料和补充目标；右侧汇总这次要做什么。默认 10 道，正式版范围 1～30；无材料也能做主题训练题。示例输入、用户笔记和任务成果分别标来源。

### 生成与检查

执行页显示处理步骤和取消。候选页提供题干、要点、追问及来源，支持编辑、选择和部分保存；只有确认保存才进入题库。当前生成和校验是交互演示，不按粘贴内容真实推导问题，也未完成真实语义查重。

正式版需补充：字段错误对应到题目、规范化重复比较、失败恢复、保存操作 ID、新增/更新/跳过统计。生成超时保留输入，不默认保存不完整候选。

截图：[范围](../../prototypes/workbench-ui/output/playwright/02-question-setup.png) · [候选](../../prototypes/workbench-ui/output/playwright/03-generated-questions.png)。这些截图用于结构参考，当前材料范围以 UI03 与原型实际页面为准。

## 8. UI05 · 题库

页面上方为数量和主要入口，下面岗位、搜索、主题、难度筛选；主区为可选择题目列表与详情。右栏展示题干、要点、追问和来源，并支持编辑、加入复习、开始单题练习。

- 列表和详情使用同一筛选结果。无结果时清楚展示空态，不留筛选外题目的详情。
- 全选只针对当前筛选结果。手选一道题开始就只有一道主问题。
- 岗位切换重置主题，避免旧主题造成不可解释的空列表。
- 示例题仍带来源标记。正式首次启动题库为空，示例需单独体验，不能当真实内容数量。
- 原型支持岗位、关键词、主题、难度；PRD 中来源、复习状态筛选和题目归档/JSON 导出仍待实现。
- 题目修改可在原型保存，但正式版必须形成新版本，不改旧面试快照。

## 9. UI06–UI07 · 面试准备与面试进行中

### 9.1 准备页

选择主方向、训练/模拟、文字/语音、软时长、题数和题目范围。启动后保留本轮参数，后改默认设置不改变已开始面试的追问上限。

默认 20 分钟、5 道主问题、最多 2 次追问。手选少量题时按实际数量。正式版题不足应提示补题/减题，当前原型普通默认队列仍可能重复示例凑足预设数量，这一差距不隐瞒。

### 9.2 进行中

中间当前问题卡、回答输入与提示/不知道/跳过；右侧主问题进度、已提交回答、来源。追问替换当前问题，但原回答仍可回看。主问题进度不按追问次数累加。

文字提交有空值提示；原型记录用户原话，追问和反馈为固定示例。正式版需提交状态、可恢复错误、真实引用回答的追问，不能把演示文案当个性化评价。

训练模式每题结束给反馈；模拟模式结束后反馈。提示使用、跳过和不知道保留到报告。软时长是引导，不截断正在输入的回答。

### 9.3 逐轮语音状态

`未配置 / 未授权 → 就绪 → 录音中 → 已停止 → 转写中 → 核对文字 → 提交 → 本轮记录`

失败可重试/改文字；停止不等于提交。正式单次最多 3 分钟，原型是最多 30 秒的演示计时，既不访问麦克风也不上传音频。确认文字后再评价内容，不从演示流程推断语速或发音。

## 10. UI08 · 报告、笔记与归档

### 10.1 报告结构

- 顶部目标：“把这次的卡点，变成下次的进步。”操作为面试记录、导出 Markdown。
- 概览显示方向、模式、涉及主问题数、提示使用和跳过/不知道次数。
- “保留 / 补上”分区，用具体下一步代替一个总分。原型反馈明确标固定示例，用户真实能力没有被评分。
- 逐题对照左为原回答、右为参考方向，保留文字/语音、提示使用和主问题/追问位置。
- 右栏只推荐一件小补练，包含加入复习和打开复习清单。
- 底部独立复盘笔记与保存按钮；不覆盖原回答或生成反馈。

### 10.2 保存与交接

结束面试保存归档快照；浏览旧报告不替换正在进行的面试。报告示例独立标识，重复打开不创建多份。笔记显式保存后可刷新找回。加入复习按关联原题去重；没有可用回答时不能随意塞入第一道示例题。

当前 Markdown 导出只包含旧版逐轮问题、回答与提示记录，尚未纳入新报告笔记、完整反馈和来源；正式导出内容以 PRD 为准。报告搜索和反馈重生成版本尚未实现。

## 11. UI09 · 复习清单与回忆

列表按全部、还没练过、有练习记录筛选，显示题目、主题、来源方向、最近尝试及是否借助参考；提供开始回忆、单题面试和移除。

回忆页先只有问题和草稿，不暴露答案。用户选择“写完了，对照要点”才展开参考与小练习建议；同一草稿一旦看过参考，刷新重开仍记录辅助。自评为“还需要补练 / 我能讲清楚了”，只保存本次尝试，不自动移出清单或永久标掌握。下一次尝试从新草稿开始。

原型保留练习内容、辅助标记、自评和时间；草稿持久化依赖页面离开/其他保存事件，尚未达到 PRD 的 800ms 保存目标。20～30 分钟小练习目前是通用静态建议，不是按课程生成与验证的真实编程作业。

正式版显示未保存状态和保存失败，练习失败不清空草稿；提醒和课程自动排期属于后续能力。

## 12. UI10 · Agent 配置

两个内置 Agent 使用稳定任务流程。自定义配置可以创建/重新编辑名称、任务说明、模型引用和允许工具；当前模型固定展示共用 DeepSeek。

配置对话框将工具与提示词分开，显示“读取选定资料”“保存候选题草稿”开关及范围。保存配置并不执行工具；原型没有实际权限服务。正式版新任务保存配置版本，权限取服务启用、Agent 允许和本次任务范围的交集；提示词不能改变内置面试阶段。

空名或空说明应定位到输入；取消保留原配置。当前原型支持基本必填检查，本地保存与重新编辑。

## 13. UI11 · 默认设置、模型、语音和 MCP

### 默认设置

候选数、软时长、主问题数、追问上限分组呈现；保存只影响新任务。默认值来自 PRD，第 2 节不是对每个示例数值的用户逐项批准。

### 模型与语音

文本模型、语音服务分别显示地址/模型信息、密钥状态、连接测试、成功/失败状态。当前密钥输入禁用，测试均为演示；没有任何真实账号配置。正式版凭据存系统安全存储，最小测试不带项目材料。

### 工具与 MCP

左侧示例本地服务、stdio 启动形式、工具列表与启用开关、成功/超时状态演示；右侧说明路径和权限边界。连接状态与工具允许状态分开。

当前开关只改变当前页面的设计状态，未持久化权限，也不会据此执行真实命令。示例调用按钮用来查看成功或超时文案，不能证明实际工具执行遵守了开关。正式实现需要结构化可执行文件/参数、工具发现、输入输出、真实超时/取消和权限拦截。

## 14. UI12–UI13 · 记录与后续入口

任务记录包含全部、进行中/待处理、已保存成果、草稿，点击回到原上下文和结果。面试档案独立列方向、模式、回答数量及是否写过笔记。初次无记录时引导创建任务，不伪造真实使用次数。

## 15. 响应式与可访问性

- 桌面日常目标 1280×800 及以上，重点 1536×1000；原型另外检查 1024/768/390px。
- 任务检查区在不超过 1020px 时上下排列；材料列表/预览在不超过 760px 时单列。
- 报告/回忆在不超过 960px 时调整辅栏，报告逐题对照在不超过 520px 时上下排列；MCP 不超过 1020px 时单列。
- 窄屏将侧栏收为图标，保留主要入口；长标题折行。390px 是压力检查，不表示首版包含手机 App。
- 输入有 label，按钮有可读文字或 aria-label，工具开关使用 switch 状态，状态不只用颜色。核心输入不依赖 hover。
- 正式版还需实际 Windows 缩放、Tab 顺序、弹窗焦点返回、长文本、屏幕阅读器及错误提示的人工检查，浏览器不溢出测试不能替代这些验收。

## 16. 状态、文案与交付核对

| 场景 | 用户应看见 | 不应出现 |
| --- | --- | --- |
| 无材料/无题/无报告 | 原因、添加或下一步入口 | 不明原因的空白、示例混充真实数量 |
| 生成/提交中 | 当前步骤、可取消或等待状态 | 无期限“思考中”且不能退出 |
| 等待用户 | 检查候选、核对文字或回答 | 假装模型仍在持续执行 |
| 写入成功 | 已确认保存和归属位置 | 仅按按钮就提示成功 |
| 失败/中断 | 出错步骤、输入仍在、恢复动作 | 刷新自动重发或静默丢失 |
| 来源不足 | 示例/待核对/依据不足 | 编造课程时间、代码行号或招聘真题 |
| 权限/网络缺口 | 哪个动作被阻断、如何恢复 | 将提示词或模拟成功当真实权限 |

本轮交付完成页面结构、可点击主链、现有交互验证和文档。真实服务、状态持久化、版本与权限、完整导出和首版正式验收仍见[差距清单](2026-10-18-design-coverage.md)。
