## 已确认的产品定位

用户需要一个参考 WorkBuddy 功能与交互的 Windows AI 工作台，面试准备和学习复盘是首批应用。用户明确接受先开发面试题整理与 AI 面试官，再完善课程复盘。平台需要能继续添加 Agent、接入工具并保留会话和成果。

既有约束保持：允许选定材料通过云端处理，主模型选择 DeepSeek；面试支持文字与语音；用户有 5 年 Java 开发经验，目标覆盖 Java、Python 后端兼 AI、Agent 应用开发；没有现成题库，需从零建立。

### 统一执行层的必要边界

- 内置 Agent 共用模型、资料和题库工具，各自维护任务说明及流程状态。面试提问、回答、追问有明确状态，不由任意 Agent 同时接管。
- 先提供任务/Agent 切换与明确的阶段交接；自动调度多个 Agent 不是用户已经确认的需求。
- 取消要传播到正在进行的模型或语音请求；重试需要避免重复入库、重复保存报告和重复外部写入。具体幂等规则在完整设计中定义。
- 恢复指读取已保存进度、由用户选择继续；不能假定被中断的外部请求已成功或自动重复所有动作。
- 执行轨迹展示任务步骤、工具请求与结果摘要及必要的出处，不将模型内部思维链当作可承诺功能。
- 权限与可见范围绑定用户选定的项目和材料；语音面试仅在用户主动开始时采集麦克风，录音状态可见、可停止。
- 模型密钥通过桌面安全存储保存，不进入前端配置、日志或生成报告。
- 桌面交互、本地任务/数据和模型/工具适配保持清楚边界；是否拆独立后台进程、使用哪种协议及是否采用 ACP 还未决定，不照搬 WorkBuddy 的全部进程数量。

## 首批应用与交接

### 面试题整理 Agent

- 从目标岗位、课程知识点及选定项目源码生成候选训练题，分类并提示重复项，补充回答要点、追问与来源；近似题由用户比较，不自动合并不同考察角度。
- 共用知识点，按 Java / Python 后端兼 AI / Agent 应用开发打标签；保留题目与回答的版本。
- 模型生成题标明生成来源；只有经过实际检索核对的材料才能标记为真实面经或官方依据。
- 可选题目进入一次模拟面试，而不是将整份聊天转交给面试官。

### AI 面试官 Agent

- 每轮选择岗位方向、题目范围与输入方式，以文字或逐轮语音回答，按回答继续追问。
- 区分已有 Java 工程经验与新学 Python/AI 能力，不按 Java 年限给所有 AI 题目套同一难度。
- 语音转写先核对技术名词；本轮设计默认训练每题结束反馈、模拟结束后统一反馈，具体规则见 PRD；当前语音与反馈仍为演示。
- 保存逐题回答、具体反馈与待复习知识点，可让整理 Agent 生成候选补强题。
- 面试记录与报告必须有专门内容区，不能只留一份不可编辑的长聊天。

### 学习复盘 Agent

- 保留此前已确认的 10 分钟快速回顾和 20～30 分钟小练习两种模式，以及自动建议/手动指定入口。
- 接入课程材料、项目代码和笔记，帮助还原实现思路，生成练习与后续复习项；可向题库提交课程衍生题。
- 深造播放器画面捕获为黑屏的已知问题保留为独立输入缺口；面试模块先交付不等于视频学习需求取消。

## 桌面体验建议

建议使用工作区、Agent/任务入口、任务历史及成果预览的稳定导航，减少在多个独立聊天框之间搬运材料：

- 工作区中能看见已关联项目、课程和资料。
- 从面试题整理或面试官进入相应流程，通用会话能力共用。
- 任务内既能对话，也能查看执行状态、题目列表、来源、回答和面试报告。
- 将结果保存到题库或知识记录，之后可检索、继续训练及返回原始资料。

共用侧栏与中央三模块布局已确认，深色炭灰原型沿用该方向。题库、面试与报告按本产品用途设计，页面和状态已整理进 UI 文档。

## 推荐实施切片：尚非实施计划

1. 搭建最小桌面底座，并用面试题整理完成第一条可用任务链：模型配置 → 选范围 → 生成少量题 → 来源与回答预览 → 保存本地题库 → 重开恢复。
2. 在同一底座上接入文字及语音面试、追问、逐题记录、结果报告和待复习清单。
3. 逐步完善学习复盘、语雀保存、复习自动化与扩展工具；MCP/Skills 的扩大范围依据实际需求逐项确定。

工作台底座与面试功能交替形成可用切片，不先建一个没有可用 Agent 的庞大平台。第一版范围、保存规则、默认和验收已整理到 PRD；技术栈、实际依赖版本和语音供应商留待工程方案核验，不假定真实功能已经完成。
