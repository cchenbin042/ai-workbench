## 0. 结论先行

1. **现有设计的可靠性底座值得保留。** 单写 SQLite、操作 ID、run 栅栏、事件序号、取消边界、版本化快照、人工确认和“默认去总分”的方向，已经明显高于普通桌面原型；问题不在“要不要重做”，而在“验收是否真的能证明这些承诺”。
2. **P0 目前还不能被可执行地判定完成。** AC24 允许“真实服务或注明的可控测试替身”，而 PRD 的 P0 完成条件写的是“第 8 节真实功能验收通过”；技术方案又明确“真实服务未配置时 skipped 不能作为 M3 全部通过”。这是一个会直接导致“替身通过即宣布 P0 完成”的验收漏洞。
3. **最需要补的不是新功能，而是五个闭环证据：** 真实服务闭环（I1）、干净机发行闭环（I2）、上传前可见/可同意（I4）、数据删除与备份生命周期（I5）、报告质量与复习卡点的可测标准（I7）。
4. **两个产品语义需要用户最终拍板：** “第一版”到底是否包含课程视频讲解整理（I10）；队列任务在正常退出后应保留还是标中断（I6 的一部分）。这两个问题不应由实现默认悄悄决定。
5. **当前状态口径需要统一。** 后端 T002/T003/T005 的机制完成，不等于前端业务闭环完成；`window.workbench` 目前只放行 `system.ping`，`tasks.create` 未注册为公开 RPC，首页发送按钮仍是禁用占位。用“贯通”描述 M1 会误导后续智能体和验收。

## 2. 保留的优点

1. **可靠性与幂等设计完整。** 操作 ID 与 RPC id 分离、`write_once` 同事务提交、答案/候选/复习项唯一约束、run 栅栏拒绝迟到写入，能覆盖“提交成功但确认丢失”“取消后模型返回”等真实故障。技术方案 §3～§5，`tasks.py`/`storage.py` 的实现与 T005 测试记录一致。
2. **版本化边界清楚。** `material_versions`、`question_versions`、`report_versions`、`artifact_versions`、`agent_config_versions` 都是新增而非原地覆盖；旧面试、旧报告不被题目修订改变。技术方案 §4.2、§7.3、§8.3。
3. **人工确认优先。** 候选题必须检查后入库、转写必须核对后提交、工具副作用需要授权、复习自评不自动等于掌握。PRD FR03/FR06/FR08/FR11；技术方案 §8.4、§10.2。
4. **范围与隐私意识强。** 工作区隔离、原项目只读、默认排除凭据、发送前预算检查、密钥只存系统安全存储、导出排除密钥、MCP 明确“路径校验不是操作系统沙箱”。技术方案 §6.1、§10.3、§11。
5. **报告方向正确。** 默认不输出总分、不做语速/情绪/人格判断，要求结论指回回答或来源，接受多种合理方案。PRD FR07；技术方案 §8.3。这是比“伪精确评分”更可信的产品选择，应保留。
6. **范围纪律清楚。** 不引入向量库、ORM、Redis、LangChain/LangGraph；一次一个主动 AI 执行；等待用户不占槽；P1/P2 明确延后。技术方案 §1.3、§5.2。
7. **文档诚实。** 多处明确区分“演示/原型/正式/真实服务”，并记录课程画面黑屏、ASR 未验证、安装包缺失等限制。PRD §8 开头、设计覆盖 §3、接手指南 §8。这些限制不应在后续汇报中被“已完成”覆盖。

### I3. 资料上限与上下文预算数量级不一致，且缺少行范围选择与预算可视化

| 项目 | 内容 |
| --- | --- |
| 类型 | 确定缺陷（约束不一致）+ 取舍建议 |
| 严重度 | 高 |
| 证据 | PRD FR02（第 148 行）规定单份文本不超过 200 KB、本次原始文本合计不超过 1 MB，并说“发送前还按实际模型输入预算检查”。技术方案 §6.3（第 370 行）设置输入软预算 24,000 tokens、输出默认最多 8,000 tokens、至少 20% 余量；超预算时“让用户缩小材料/选行/分批”（第 371 行）。但 PRD 和 UI03 §6（第 119～133 行）只定义了材料勾选、预览和交接，没有行范围选择；AC01 只验证“请求仅含已选且可读材料”，没有验证预算提示或阻断行为。 |
| 缺陷/风险 | 200 KB 中文文本按 UTF-8 常见 3 字节/字估算约 6～7 万字，已远超 24k token 的材料预算；1 MB 更相差一个数量级以上。用户按产品上限选材后，很可能在点击生成时才被阻断。技术方案承诺的“选行”没有对应 UI/交互定义；实现要么违背“不静默截断”，要么频繁失败。8,000 输出 token 对 10 道含要点、替代方案、追问和来源的候选题也可能偏紧，需要实测。 |
| 影响 | M1 建题流程的主要可用性风险：用户无法预判哪些材料能发送，反复换材料；长文件无法只取相关行；候选可能因输出预算不足而缺字段或被截断。 |
| 最小修正 | 不改变 200 KB 技术防线，但补产品层：<br>1. 任务提交前显示“已选文件、版本、字符/字节、估算 tokens、剩余预算、模型/供应商”。<br>2. 提供按文件/按行范围选入；行范围生成新的材料版本，旧版本不变。<br>3. 预估超预算时在本地阻断，给出“去掉文件 / 选行 / 分批”的可执行选择，不调用供应商。<br>4. 输出预算按题数自适应；建议先实测 10 道候选的 P95 输出 tokens，再决定默认批量或单题输出上限。以下为建议值，不是用户已批准：默认 10 道时单题输出上限约 1,200 tokens；若实测不足，降为 5 道/批或提高输出预算。 |
| 可测试验收 | 用 10 KB、100 KB、200 KB、1 MB 四档中文材料：100% 任务在调用前显示预算摘要；超预算任务 0 次供应商请求并给出可操作提示；行范围选择产生新 `material_version` 且旧版本哈希不变；任意请求的估算/实际 usage 被记录；10 道候选要么全部字段完整，要么明确显示“实际 N 道”，不得截断 JSON 冒充完成。 |
| 置信度 | A（文档约束不一致）；B（具体 token 阈值与 8k 输出余量，需实测） |

## 4. 次要取舍与建议

以下不列为前十项关键问题，但建议在对应阶段顺手收敛，避免后续返工。

1. **重复题的边界要写清。** AC03 的“重复点击不增加重复记录”是操作级幂等；技术方案 §7.3 允许用户对近似题“另存/显式更新”，跨批次同内容仍可能产生两道题。建议明确“同空间规范化题干相同 → 提示；用户选择‘另存’必须二次确认”，并在 AC03 增加“跨批次同内容默认不自动入库”的断言。
2. **连接测试与单 AI 执行槽。** 技术方案 §5.2 把连接测试也放进同一协调器；长建题/面试运行时，用户点“测试连接”可能需要排队。建议保留单执行槽，但在 UI 显示排队位置，或为短连接测试保留受控控制通道，避免“设置页像卡死”。
3. **Windows 路径限制偏严。** 技术方案 §6.1 拒绝 junction/symlink/reparse point/UNC/设备路径/ADS。安全上合理，但 OneDrive、重定向“文档”目录等常见场景可能被误伤。建议先解析真实目标，若目标仍在用户选定根目录内则允许并显示规范路径；否则给出“复制到本地目录”的明确替代，而不是只报“路径不支持”。
4. **报告无总分应保留，但需要非能力型进度信号。** 不建议加招聘通过率或雷达图；可显示完成题数、提示使用、跳过/不知道、复习次数和“上次卡点”，让用户看到进步而不制造伪精确。
5. **8k 输出预算对 10 道候选偏紧。** 这是待实测项，不是已证缺陷。建议在 M1 用 3 次真实生成记录每道题的实际输出 tokens 与截断率，再决定默认批量；若 P95 接近 8k，降为 5 道/批或提高输出预算。
6. **备份加密是取舍。** 技术方案 §4.4 明确备份包含材料正文、不含密钥。建议在数据管理页提示“备份是敏感文件”，P0 可不做加密，但应给用户“保存到受控位置”的说明；若未来做加密，不把密码放入备份。
7. **报告搜索/归档/音频删除缺少 AC。** FR07 的“搜索报告”、FR04 的“归档”、FR06 的“删除原音频”在 AC 中没有独立用例。建议并入 AC21/AC28 或新增小用例，避免功能写了但没验收。

### 8.3 回应 Claude Code 的 5 个问题

#### Q1. Task 04 后移是否真的省事？

**结论：部分同意，但不支持把完整 Task 04 后移；支持“主题路径质量 spike”，不支持把官方 M1 重排成“先题库后资料”。**

- **但不能说没有返工：** 当前 `TaskService._row` 在 `workspace_id` 非空或 scope 不是 `local` 时直接 `SOURCE_OUT_OF_SCOPE`（`tasks.py:37,147`）；`TaskService.create` 把 scope 固定为 `local` 并只保存 `material_version_ids`（`tasks.py:129`）。这说明真实工作区/资料归属的正式接线还没做，Task 04 之后仍要改任务创建和归属校验的集成点，不是“把资料列表传进去”就结束。M1 计划 Task 03 也明确“测试流程的 workspace/agent 引用暂为 null；Task 04/05 接入后必须验证真实空间与 Agent 版本归属”。

#### Q2. 安装包门禁后移的风险是否被低估？有没有更轻的检查？

**结论：同意风险存在；支持“早期最小打包探针”，反对把正式干净机门禁静默后移。**

- 接手指南 §7 已说明：`npm --prefix apps/desktop run package` 能生成桌面壳，但完整 `build.ps1 -Stage M1` 需要 PyInstaller 服务包；当前缺 `.venv/Scripts/pyinstaller.exe` 和 `services/workbench/dist/workbench-service`。G01/G04 也记录服务包与 Job Object 缺口。若等到 M3 才发现 PyInstaller 资源路径、Electron 资源复制、子进程树清理的结构性问题，确实可能返工已完成代码。
- 更轻的探针：只做一次 `PyInstaller onedir`，放进 Forge `resources`，启动服务并完成 `system.initialize/ping` 握手；退出后检查本应用拥有的进程是否清理。它不要求干净机、不要求安装器、不要求签名，但能提前暴露“服务包缺失/路径错误/握手失败/进程残留”四类高风险。探针结果写任务明细，不替代 P0 发行验收。

#### Q3. “自定义 Agent + MCP”在 P0 的必要性

**结论：内置两个 Agent + 版本化配置/切换是已确认基线；自定义 Agent 是设计默认，MCP 的记录有冲突但本轮按协调者口径保留基线，不把任何一项移到 P1 或取消。**

#### Q4. 同题“首次 vs 复练”的 gaps 比较是否会诱导背答案？

**结论：同意风险；改为“同一知识点、不同角度/不同题”的迁移验证，并记录是否看过参考；不做统计门禁。**

- 同题复练确实可能奖励记住参考要点，和 PRD §1.2“不使用背中固定参考措辞”冲突。更合适的可观察信号是：同一知识点换一个新题、换一个追问角度（原理/边界/取舍/验证）、要求举一个新例子或解释一个反例；第二次尝试前未查看参考答案或未使用提示（复习记录看 `reference_seen_at`，新面试看 hint 记录），或明确标“借助参考”。
- 比较对象应是“知识点层面的 gaps/uncertain 是否减少、提示使用是否减少、能否回答新角度”，不是逐字比对参考答案。人工复核只看证据是否可查、是否接受合理替代方案、是否把“未提及”误判为“不会”；争议标 uncertain。
- 这不是统计准确率，也不证明学习提升；它只是产品试用记录。协调者第 3 条与此一致。
